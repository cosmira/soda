# RFC: новые проверки против лишних абстракций и повторяющихся решений

**Статус:** оба правила включены по умолчанию по решению владельца проекта.
**Изменение решения:** владелец явно выбрал включение в стандарт и публикацию в master.
Эмпирический порог 20 находок не пройден; это исключение из исходного условия допуска,
а не новая оценка точности. Историческая матрица и результаты ниже сохранены.
**Область:** общий PHP, без конвенций Laravel.
**Совместимость:** в стандарт добавлены две проверки; явные списки правил и JSON schema 4 сохранены.

## 1. Цель и основания

Устранять конкретную лишнюю работу при чтении и изменении кода: переходы без
полезного поведения, механические обёртки и копирование одного решения.

DHH и Тейлор Отвелл задают приоритеты через опубликованные принципы. Они не
участвовали в RFC и не одобряли эти правила. Матрица ниже — интерпретация автора;
ревью корпуса выполнено одним ассистентом, без независимой экспертной комиссии.

| Источник | Основание | Вопрос для проверки |
| --- | --- | --- |
| DHH, [Pattern vision](https://signalvnoise.com/posts/3341-pattern-vision) | Применение паттернов требует контекста | Удаляем ли реальное усложнение в данном примере? |
| DHH, [Concerns](https://signalvnoise.com/posts/3372-put-chubby-models-on-a-diet-with-concerns) | Связанное поведение можно организовать внутри модели без разрастания числа объектов | Понятнее ли вызов; достаточно ли метода или trait? |
| Taylor Otwell, [Tuple, 24 января 2024](https://podcast.tuple.app/episodes/taylor-otwell-creator-of-laravel/transcript) | Код должен легко меняться; подготовка ко всем будущим требованиям усложняет его | Меньше ли мест меняется для текущего сценария? |

Правило допускается, если нарушение наблюдаемо в PHP, есть исправление с
сохранением поведения и полезный контрпример, появляется новое покрытие и не
требуется создавать объект ради прохождения проверки. Матрица принципов
проверяет идею; тесты проверяют алгоритм; корпус проверяет полезность находок.

## 2. Пять кандидатов и решения

### A. NoPassThroughLayers — не добавлять

```php
final class ReportService
{
    public function __construct(private ReportManager $reports) {}

    public function generate(int $id): Report
    {
        return $this->reports->generate($id);
    }
}

final class ReportManager
{
    public function __construct(private ReportGenerator $reports) {}

    public function generate(int $id): Report
    {
        return $this->reports->generate($id);
    }
}
```

Если эти границы не имеют отдельной роли, вызов можно сократить до
`$generator->generate($id)`. Существующий `NoTrivialDelegatingClasses` уже
обнаруживает обе обёртки по отдельности. Новый граф ради более длинного сообщения
не оправдывает отдельное правило.

Контрпример — слой с авторизацией:

```php
public function generate(int $id): Report
{
    $this->access->authorize($id);

    return $this->generator->generate($id);
}
```

### B. NoTrivialFactories — реализован узкий исследовательский кандидат

До:

```php
/** @internal */
final class ReceiptFactory
{
    public function create(int $amount, string $currency): Receipt
    {
        return new Receipt($amount, $currency);
    }
}

$receipt = $factory->create(1000, 'EUR');
```

После проверки вызывающего кода:

```php
$receipt = new Receipt(1000, 'EUR');
```

Контрпример — преобразование данных и использование зависимости:

```php
public function create(Order $order): Receipt
{
    return new Receipt(
        $order->total(),
        $this->currencies->forCountry($order->country()),
    );
}
```

Именованный конструктор `Money::euros($amount)`, возвращающий
`new self($amount, 'EUR')`, также не является нарушением.

**Критерий срабатывания:**

- Именованный `final` класс с настоящим PHPDoc-тегом `@internal`.
- Нет родителя, интерфейсов, traits, атрибутов, свойств и констант.
- Единственный метод — публичный нестатический `create` (без учёта регистра PHP).
- Ровно один оператор: `return new ConcreteClass(...)`.
- Каждый обязательный параметр передан один раз, позиционно и в исходном порядке.
- Нет defaults, ссылок, variadic, именованных или распакованных аргументов.
- Нет атрибутов метода/параметров или возврата по ссылке: они могут нести контракт.
- Нет динамического класса, анонимного класса, `self`, `static` или `parent`.
- Пустые списки параметров и аргументов допустимы. Имя класса роли не играет.

Сообщение указывает класс, `create`, создаваемый тип и строку метода:

```text
ReceiptFactory::create() only constructs Receipt and forwards all parameters
unchanged. Consider constructing Receipt at the call site.
```

`@internal` сужает область, но не доказывает отсутствие полезного контракта.
Автоисправления нет. При удалении фабрики проверить именованные вызовы, типы
параметров и результата, strict_types и зависимости от её собственного типа.

### C. NoAnemicModelOperations — отложить

До:

```php
final class InvitationService
{
    public function accept(Invitation $invitation): void
    {
        if ($invitation->status === 'pending') {
            $invitation->status = 'accepted';
        }
    }
}
```

Возможное улучшение — перенести операцию в `Invitation::accept()` и вызывать
`$invitation->accept()`. Но операция над `ExternalInvitation` сторонней библиотеки
может иметь ту же форму, хотя перенос невозможен. Внешний сервис также может
реализовывать политику конкретного процесса.

AST не раскрывает владельца бизнес-правила. Суффиксы `Service`, `Model`, `Entity`
не решают эту проблему. Оставить рекомендацией для ревью.

### D. NoRepeatedCompoundConditions — реализован исследовательский кандидат

Название уточняет исходное NoRepeatedDomainDecisions: проверка распознаёт
структурный повтор, а не смысл предметной области.

До:

```php
final class Subscription
{
    private bool $active = true;
    private bool $suspended = false;

    public function renew(): void
    {
        if ($this->active && ! $this->suspended) {
            $this->extendPeriod();
        }
    }

    public function sendRenewalNotice(): void
    {
        if ($this->active && ! $this->suspended) {
            $this->sendNotice();
        }
    }

    public function showRenewalOffer(): void
    {
        if ($this->active && ! $this->suspended) {
            $this->showOffer();
        }
    }
}
```

После: добавить `private function canRenew(): bool`, возвращающий это условие,
и заменить все три условия вызовом `$this->canRenew()`. Проверка состояния
продолжает происходить при каждом вызове; значение не кешируется.

Контрпримеры: одиночное `if ($this->active)`; похожие условия у Invoice и Shipment;
одинаковое выражение, которое представляет разные решения и может меняться
независимо. Последний случай требует человеческой оценки.

**Критерий срабатывания:**

- Одинаковое условие в минимум трёх разных методах одного именованного класса.
- Минимум один `&&` или `||`; остальные разрешённые узлы — литералы, прямые
  чтения объявленных нестатических свойств `$this`, `!`, `===`, `!==`.
- Числовой знак перед литералом поддерживается; другие арифметические операции нет.
- Объявленные свойства включают constructor promotion.
- Классы с наследованием, traits, `__get`, `__set`, `__isset`, `__unset` или
  property hooks (включая promoted hooks) пропускаются целиком.
- Вызовы, локальные переменные, вложенный/динамический доступ, присваивания,
  ссылки на именованные константы и прочие выражения исключаются.
- Проверяются if/elseif, while/do/for и тернарные выражения. В `for` учитывается
  только последнее условное выражение; предыдущие не управляют продолжением цикла.
- Вложенные closures, arrow functions, функции и классы не относятся к методу
  владельца. Именованные вложенные классы анализируются отдельно.
- Форматирование, комментарии и позиции игнорируются. Тип литерала, значение,
  порядок операндов и структура сохраняются. Алгебраического упрощения нет.
- Повторы в одном методе дают один вклад в порог.

Одна диагностика на группу: самая ранняя строка, количество методов и все места.
`value` — число методов; `threshold = minMethods - 1` — наибольшее разрешённое
число. `minMethods < 2` вызывает `InvalidArgumentException`.

```text
The same compound condition appears in 3 methods: renew() at lines 9;
sendRenewalNotice() at lines 16; showRenewalOffer() at lines 23.
Extract a named predicate if these occurrences express the same decision.
```

Никакого автоисправления или автоматического выбора имени предиката.

### E. NoMirrorConfiguration — отклонить для общего PHP

```php
return [CsvExporter::class, JsonExporter::class, XmlExporter::class];
```

Список может задавать разрешённые реализации, порядок или стабильную комплектацию.
Автопоиск меняет поведение при добавлении файла. Без установленной конвенции
конкретной системы нарушение определить нельзя.

## 3. Матрица оценки принципов

Все оценки — интерпретация, не голоса названных разработчиков.

| Кандидат | Критерий DHH | Критерий Отвелла | Проверяемость | Решение |
| --- | --- | --- | --- | --- |
| Прозрачные слои | Удаление переходов упрощает вызов | Меньше связанных мест | Высокая для простого случая | Уже покрыто |
| Фабрики | Прямое создание иногда понятнее посредника | Исчезает механическое повторение сигнатуры | Шаблон точный; полезность не доказана | Исследовательский |
| Внешняя операция над моделью | Поведение может принадлежать модели | Перенос должен упрощать реальные изменения | Владелец решения неизвестен | Отложить |
| Составные условия | Именованный предикат может улучшить вызов | Одно решение меняется в одном месте | Структура точная; общий смысл неизвестен | Исследовательский |
| Зеркальная конфигурация | Конвенция должна существовать заранее | Автопоиск может добавить скрытую сложность | Недостаточна без контекста | Отклонить |

## 4. Реализация и интерфейс

Поставляемые детекторы находятся в `src/Rules/Structure` и `src/Rules/Complexity`.
Их исходные замороженные версии сохранены в [исследовательском каталоге](../research/explicit-behavior/README.md).
Оба прямо наследуют `Check`, реализуют `checkFile()` и `requiredAnalyses(): []`.
Используется уже разобранный AST; новый парсер в правилах и межпроектный граф не
добавлялись. Исследовательский harness сам разбирает донорский код, не выполняя его.

Публичные пространства имён:

```php
use Cosmira\Soda\Rules\Structure\NoTrivialFactories;
use Cosmira\Soda\Rules\Complexity\NoRepeatedCompoundConditions;

return Soda::configure()->withPaths(['src/'])->with([
    new NoTrivialFactories(),
    new NoRepeatedCompoundConditions(minMethods: 3),
]);
```

Этот API доступен через Composer autoload. Проверки входят в стандартный набор;
`require_once` нужен только для исторических снимков исследовательского алгоритма.
Стабильные id: `no_trivial_factories`, `no_repeated_compound_conditions`.

Записи включены в каталог, `list:rules`, стандартный набор и генерируемый `init`.
Вручную подключённые исследовательские проверки уже используют обычный путь CLI:
нарушение даёт exit 1, пустая конфигурация — exit 0, JSON сохраняет schema 4.

## 5. Проверка и фактический результат

Тесты покрывают положительные примеры, исключения, аргументы фабрики, границы
порога, литералы и порядок выражений, разные классы, вложенные области видимости,
циклы, тернарные выражения, promoted properties/hooks, позиции и сообщения.
Интеграционный тест запускает реальную консольную команду с PHP-конфигурацией и
JSON-отчётом. Поведенческие тесты сравнивают создание объекта и порядок эффектов,
а также повторное вычисление предиката после изменения состояния.

Порог допуска: минимум 20 рассмотренных находок на кандидат, не менее 90%
полезных, до 50 находок на ревью и минимум 20 похожих случаев без срабатывания.
При недостатке материала кандидат остаётся исследовательским.

Алгоритмы зафиксированы SHA-256 в [manifest.json](../research/explicit-behavior/manifest.json)
до запуска. Решение после исследовательской части записано в
[discovery-decision.md](../research/explicit-behavior/discovery-decision.md) до
анализа отложенной части. Алгоритмы и пороги не менялись между частями.

| Проект | Часть | PHP-файлы | Фабрики | Повторяющиеся условия |
| --- | --- | ---: | ---: | ---: |
| Soda | Исследовательская | 178 | 0 | 0 |
| Monolog | Исследовательская | 125 | 0 | 0 |
| Symfony Console | Отложенная | 177 | 0 | 0 |
| Guzzle | Отложенная | 70 | 0 | 0 |
| **Всего** | | **550** | **0** | **0** |

Версии проектов и хеши исходных деревьев: [results.json](../research/explicit-behavior/results.json).
Soda проверена в текущей рабочей копии; commit отдельно не описывает её незакоммиченные
изменения. Хеш дерева фиксирует именно проанализированные файлы.

По пять похожих классов из каждого проекта для каждого кандидата отобраны
детерминированно: всего 40 оценок, по 20 на правило. В
[nonfinding-review.json](../research/explicit-behavior/nonfinding-review.json)
сохранены места, короткие выдержки, наблюдения и обе оценки принципов.
Пул широкий (классы с `new`/`create` или `&&`/`||`), поэтому многие контрпримеры
отсеиваются уже по границам класса или выражения. Это слабое свидетельство
полезности, не измерение полноты или точности находок.

Например, в Guzzle `closed || closing` встречается в двух методах CurlMultiHandler;
похожие проверки в других методах включают вызовы или отличаются структурой.
Нулевая выдача отражает ограничения кандидата, а не отсутствие возможных улучшений.

**Исторический итог исследования (до решения о включении):** минимальные 20 находок не набраны ни для одного кандидата. Точность
неизмерима (не 100%). Оба остаются в research; поставляемые правила и стандарт
не меняются. Для повторного рассмотрения нужен дополнительный корпус приложений,
без подгонки порогов под желаемый результат. Синтетические тесты не заменяют
эмпирическое подтверждение и не входят в число находок корпуса.

## 6. Решение о включении по умолчанию

По явному запросу владельца оба кандидата стали стандартными проверками.
Критерии распознавания и порог трёх методов сохранены. Продуктовая реализация
разделяет обход области видимости и вычисление структурного отпечатка;
исследовательские снимки и их хеши не изменены.

При запуске без конфигурации новые нарушения дают exit 1. В существующий
явный `with([...])` правила автоматически не добавляются. Пользователь может
выбрать собственный список или изменить `minMethods`.

Нулевой результат корпуса не означает подтверждённую точность. Отмена
исследовательского условия допуска зафиксирована как осознанная политика проекта.
