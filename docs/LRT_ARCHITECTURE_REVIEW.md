# Независимое ревью миграции Soda на phplrt

Дополнение после проверки числовых допусков: прежний зелёный self-quality
учитывал `MethodsFollowCallOrder(40)` и скрывал 38 нарушений. Это ограничивает
прежнюю оценку простоты. Допуски удалены из проверки порядка методов и трёх
правил PHPDoc; все 38 нарушений исправлены перестановкой объявлений в 20 файлах.
Сравнение AST подтверждает сохранение тел, атрибутов и комментариев методов.
Текущий полный suite: **715 тестов / 7809 assertions**; self-quality — **0**
без числового допуска. Матрица и benchmark ниже относятся к предыдущему этапу.

Дата: 2026-09-10. Статус: **миграция и последующая очистка проверены;
архитектурная оценка — 90/100, все выполненные локальные проверки зелёные**.

После первого ревью пользователь поручил исправить недостатки и подтвердил
обязательное соблюдение текущего `soda.php`, включая многострочные PHPDoc методов,
свойств и констант. Self-quality теперь даёт **0 замечаний вместо 374**.
Полный suite: **715 тестов / 7807 assertions**; performance: **2 / 6**.
Pint, PHPStan и Rector проходят. Это локальная проверка на PHP 8.5.4;
удалённая матрица CI ещё не запускалась.

В ходе очистки удалены 16 классов и добавлены 5 с конкретными обязанностями:
исходников PHP стало 304 вместо 315. Объединены сборщики метрик callable,
убраны пересылающие классы движка и два вложенных контейнера метрик.
API остаётся одним вызовом `Rule`. Текущий benchmark: **2,54×** для одного
сценария выборочного анализа при 91 одинаковом violation в обоих режимах.
Подробности — в [RULE_EXPRESSIONS.md](RULE_EXPRESSIONS.md), путь исполнения —
в [PROJECT_FLOW.md](PROJECT_FLOW.md).

Задача реализации: «Переписать проект на LRT», `01a0890f-eb78-71d1-b86c-5230974907d8`.
Задача ревью: `01a0891a-105e-7432-a4a0-f1ee2d91235c`.

Пользователь требует более мощные правила, ускорение, зрелый анализ и прежде
всего понятную, простую в поддержке архитектуру. Первое ревью включало связь с исполнителем и независимую проверку исправлений.
После завершения его задачи ревьюер выполнил отдельно порученную очистку.
Исходники одновременно с исполнителем не редактировались.

Это оценка по публичным инженерным принципам десяти разработчиков, а не их
реальные отзывы, голоса или одобрение проекта. Критерии и веса выбраны ревьюером.
Тейлор Отвелл и DHH имеют наибольший индивидуальный вес. Источники обосновывают
принципы; конкретные выводы о Soda принадлежат ревьюеру.

## Архитектурные решения

1. **Принять phplrt для выражений правил.** Это соответствует запросу на составные
   условия и небольшую грамматику. [phplrt](https://phplrt.org/) — инструментарий
   для языков; замена им полноценного PHP parser потребовала бы отдельного
   обоснования и поддержки PHP-синтаксиса. Nikic AST остаётся источником фактов.
2. **Сохранить один пользовательский конфиг и существующий вывод.** Выражения
   входят в `soda.php`; отдельный язык конфигурации и второе дерево отчётов не нужны.
3. **Собирать грамматику при разработке.** Исходная грамматика и генерируемый parser
   поставляются вместе, compiler остаётся dev-зависимостью. Требуются проверка
   воспроизводимости и проверка установки зависимостей без dev.
4. **Разрешить выборочный анализ с консервативным fallback.** При наличии старых
   или пользовательских проверок запускаются все анализаторы. Это понятное
   ограничение, которое сохраняет совместимость без нового протокола плагинов.
5. **Не требовать минимального количества строк любой ценой.** Явный список
   посетителей лучше скрытого обнаружения. Небольшая грамматика оправдана новой
   возможностью; новые пустые wrappers — нет.

Ожидаемый путь: `soda.php → Rule → RuleExpression → требуемые анализаторы →
PHP AST и факты → Rule::evaluate → существующий отчёт`.

## Что упрощено и почему

- `QualityAnalyser` разрешает конфигурацию и собирает движок напрямую;
  `QualityEngine` создаёт контекст, агрегирует namespaces и исполняет checkers.
  Удалены три пересылающих класса, прежний API сохранён.
- `CallableMetricsVisitor` заменяет пять отдельных visitors. Один стек владельцев
  сохраняет границы методов, функций, closures и анонимных классов. Связанные
  flow-метрики собираются вместе; выбор одного такого факта собирает и соседние.
- `MethodMetricsData` хранит пять именованных наборов метрик без двух вложенных DTO.
  `FileRules` заменяет два почти одинаковых checker. Member-scanner напрямую
  собирает типы сигнатур, операций с классами и catch без трёх посредников.
- `PropertyMetrics`, `TraitAdaptations` и `ArchitectureDeclarationProbe` имеют
  отдельные предметные обязанности и разгружают большие visitors/extractor.
- Начальные правила и тексты рекомендаций — явные данные в
  `resources/rule-initializers.php` и `resources/structural-rule-advice.php`.
  Они поставляются вместе с `resources/rules.php`; не нужен генератор или
  автоматическое обнаружение классов во время запуска.
- Сложные условия получили именованные предикаты с сохранением ленивого
  вычисления. Реализации базового контракта обозначены `#[Override]`.
  Добавлены обязательные многострочные PHPDoc. Пороги Soda и её правила
  приёмки не ослаблялись.

В Pint явно установлен `ordered_interfaces: false`. Существующее правило
LayerMixing считает первый интерфейс основной ролью класса; алфавитная
перестановка `StandardPlugin` меняла смысл этого контракта. Сохранены исходный
порядок интерфейсов и поведение анализатора; глобальные Pint/Rector проходят.
Это настройка форматтера, которую нужно учитывать при дальнейших изменениях.

## История первого ревью

Первое ревью завершилось оценкой 87,5/100 при 374 self-quality findings и
красных глобальных Pint/Rector. Это было явно зафиксированное ограничение,
а не зелёная приёмка проекта. Тогда независимо проверены R1–R6, 23 комбинации
scope/field, границы callable и зависимости через attributes. Snapshot из
315 файлов дал 92 одинаковых violations и 2,89× в одном сценарии. Установка
имеющегося lock без dev прошла без сетевой загрузки пакетов.

Пользователь затем поручил исправить недостатки. Для этого этапа сохранён
отдельный baseline с 374 findings; включение трёх правил PHPDoc было явно
подтверждено пользователем. Все эти замечания закрыты текущим кодом.

## Границы проверки

Локально выполнен PHP 8.5.4. Найденные пути PHP 8.3 и 8.4 оказались ссылками
на тот же 8.5.4. Матрица GitHub Actions 8.3.18/8.4/8.5 настроена, но выполнение
на минимальной версии и удалённый CI здесь не подтверждены.

Статический анализ не доказывает полную семантику PHP: динамические имена,
внешнее наследование и вызовы через reflection имеют ограничения. Старые
правила используют полный набор анализаторов; часть специализированных
проверок сохраняет отдельный parsing. Общая база всё ещё содержит несколько
исторически разных подсистем. Выносить их в новый универсальный framework
ради одинаковой формы не требуется.

Рабочее дерево было грязным до миграции. Общий git diff нельзя целиком
приписывать текущей очистке; числа 16 удалённых / 5 добавленных классов получены
