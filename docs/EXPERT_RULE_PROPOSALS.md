# Expert Rule Proposals

This document keeps the continuous-improvement matrix explicit: expert perspective, code evidence, rule proposal, and expected detector behavior.
`DocumentationContractTest` protects this table shape, required experts, evidence markers, proposal action markers, and behavior verbs.

| David Heinemeier Hansson | Hidden side effects inside conditions make code harder to read at the speed of application code. | A condition can contain `if ($a = $b)`, where reading and mutation happen in one expression. | Add `no_assignment_in_condition` rule. | Parse control-flow conditions and report `Assign` / `AssignOp` nodes found inside `if`, `elseif`, `while`, `do while`, `for`, and ternary conditions. |

| Fabien Potencier | Framework-quality code should avoid constructs that static tools and reviewers routinely misread. | A single `=` near comparison code is visually ambiguous. | Add an AST-backed structural smell rule. | The rule should parse PHP-Parser nodes instead of regex so nested expressions are reported consistently. |
