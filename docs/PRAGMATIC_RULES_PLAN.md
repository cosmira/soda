# Soda: доказательные правила и практичная архитектура

Согласованный план от 14 сентября 2026. Исследование ниже описывает исходную версию до реализации. Текущий статус: [PRAGMATIC_RULES_PROGRESS.md](PRAGMATIC_RULES_PROGRESS.md).

База сравнения — принятый PR #1, commit `2ad5b5c07db0d02eb306afd99e2ca46b7b4e6797`. Его дерево совпадает с локальным `a926dae`. Проверены каталог из 69 стандартных правил и существующие дополнительные правила, выбранные реализации и тесты Soda. Просмотрен список 25 репозиториев CQFN. Для Aibolit рассмотрены 44 каталога детекторов и 19 каталогов метрик; для jPeek — 18 файлов метрик. Это инвентаризация, а не утверждение, что каждая реализация полностью проверена.

Зафиксированные доноры: [Aibolit `1de3705`](https://github.com/cqfn/aibolit/tree/1de37051b74fc61ce9313f350487d5807db732db), [jPeek `eb89639`](https://github.com/cqfn/jpeek/tree/eb89639b5ab0f989d239a372c759be083c07f8e6). Их полные тестовые наборы здесь не запускались. Ниже отдельно отмечены результаты запуска Soda и выводы по исходникам доноров.

**Главное решение**

Начать с улучшения стимулов существующих правил. Soda должна помогать понимать сценарий и изменять поведение рядом с его данными. Уменьшение каждого метода и класса по отдельности не гарантирует упрощения системы: оно может породить десятки посредников.

Затем переносить небольшие детекторы и проверяемые тестовые случаи. Cohesion и Cognitive Complexity исследовать как самостоятельные измерения. Не вводить новый общий рейтинг качества, замену Breathing под другим названием, ML-модель или дополнительный исполнитель.

**Что считать доказательством**

| Уровень | Что действительно установлено | Чего это не доказывает |
|---|---|---|
| Синтаксический факт | Есть определённый AST-узел, вызов, запись или связь | Что эта конструкция вредна в данном контексте |
| Корректная метрика | Формула однозначна, результат воспроизводим, границы проверены | Что любой порог отделяет хороший код от плохого |
| Полезная рекомендация | На реальных примерах изменение облегчает конкретную задачу чтения или поддержки | Универсальность для всех проектов и стилей |
| Эмпирическое подтверждение | Исследование измеряет эффект, описывает выборку и ограничения | Причинность, перенос результатов Java на PHP и пригодность любого запрета |

Aibolit в описанном исследовании обучается предсказывать Cognitive Complexity/NCSS; рекомендации меняют количества шаблонов в векторе признаков, а не исполняют реальный рефакторинг. Авторы прямо отмечают связь части результата с самой формулой сложности. Поэтому «Aibolit называет это паттерном» не является основанием для обязательного запрета. [Методика](https://github.com/cqfn/aibolit/blob/1de37051b74fc61ce9313f350487d5807db732db/wp/sections/how_aibolit_works.tex), [анализ результатов](https://github.com/cqfn/aibolit/blob/1de37051b74fc61ce9313f350487d5807db732db/wp/sections/pattern_emp_analysis.tex).

У Cognitive Complexity есть отдельная эмпирическая валидация: исследование около 24 тысяч оценок 427 фрагментов обнаружило связь со временем понимания и субъективными оценками, но смешанные результаты для правильности ответов. Это более содержательная опора, чем произвольный составной балл, однако не доказательство качества всей архитектуры. [Исследование](https://arxiv.org/abs/2007.12520).

**Какие идеи CQFN стоит перенести**

Предлагаемые имена новых классов ниже — проект API, этих правил сейчас нет.

| Приоритет | Кандидат | Что есть в Soda | Что переносить и как ограничить |
|---|---|---|---|
| Первый | `NoRedundantRethrow` | `NoEmptyCatchBlocks` не покрывает catch с throw | Маленькие fixtures EmptyRethrow. Сообщать только catch, единственное действие которого — `throw` той же переменной. Учитывать соседние catches, перехватывающие тот же тип: удаление такого catch может изменить обработку. На первом этапе без автоисправления |
| Первый | `NoEmptyFinallyBlocks` | Аналога нет | Прямой AST-детектор и positive/negative fixtures. Проверять комментарии, вложенные try, пустой finally при отсутствии catch; не предлагать синтаксически неверное удаление |
| Исследование | `MaxCognitiveComplexity` | Есть cyclomatic, nesting, conditions и returns по отдельности | Алгоритм и тестовые сценарии Aibolit сверять с определением Sonar. Считать на callable, объяснять каждое начисление. Явно определить PHP match, elseif, nullsafe, closures, recursion; не называть произвольную смесь «стандартной» метрикой |
| Исследование | `MaxDisconnectedMethodGroups` на основе LCOM4 | Cohesion отсутствует | Связи методов с состоянием и вызовами, компоненты графа. Показывать конкретные группы. Это структурная связность, не доказанное количество бизнес-ответственностей |
| Исследование | TCC | Аналога нет | Дополнительное объясняющее измерение рядом с тем же графом. Не второй дублирующий запрет по умолчанию |
| Позже | `MaxVariableUseDistance` | `UselessVariableRule` решает другую задачу | Fixtures var_decl_diff; расстояние в операторах, а не физических строках. PHP-ветви, повторные присваивания, ссылки и capture должны иметь явную семантику. Не предлагать перестановку вызовов с побочными эффектами |
| Позже, opt-in | `NoLoopCounterMutation` | Общая вложенность и условия | Fixtures mutable_index. Отдельно учитывать for-header и тело, ссылки, вложенные callable. Изменяемый курсор может быть необходим парсеру; сам факт не доказывает дефект |
| Позже, opt-in | Bidirectional counter | Аналога нет | Тесты bidirect_index полезнее blanket-запрета. У счётчика баланса увеличение и уменьшение естественны; классификация по смыслу пока не доказана |
| Не новый запрет | Nested loops, multiple try, interfaces, method counts, fanout | Частично или прямо представлены текущими метриками | Переносить дополнительные крайние случаи. Сначала уточнять различия формул, не создавать дубликаты правил |
| Не переносить как стандарт | Запреты chain/getter/setter/inheritance/static/null/arrays/имён `*Controller` | Часть политик Soda уже пересекается | Это ограничения стиля. Blanket-запрет chaining противоречит fluent API, запрет inheritance и role names — обычной практике Laravel |

Точки входа: [EmptyRethrow](https://github.com/cqfn/aibolit/tree/1de37051b74fc61ce9313f350487d5807db732db/test/patterns/empty_rethrow), [empty_finally](https://github.com/cqfn/aibolit/tree/1de37051b74fc61ce9313f350487d5807db732db/test/patterns/empty_finally), [cognitiveC](https://github.com/cqfn/aibolit/tree/1de37051b74fc61ce9313f350487d5807db732db/aibolit/metrics/cognitiveC), [var_decl_diff](https://github.com/cqfn/aibolit/tree/1de37051b74fc61ce9313f350487d5807db732db/test/patterns/var_decl_diff), [mutable_index](https://github.com/cqfn/aibolit/tree/1de37051b74fc61ce9313f350487d5807db732db/test/patterns/mutable_index), [jPeek samples](https://github.com/cqfn/jpeek/tree/eb89639b5ab0f989d239a372c759be083c07f8e6/src/test/resources/org/jpeek/samples).

**Почему донорские реализации не следует считать эталоном без проверки**

- Aibolit EmptyRethrow ищет throw той же переменной в поддереве catch. Его `CatchWithFunctions.java` специально содержит действия перед повторным выбросом и считается совпадением. Для Soda это должен быть отрицательный пример «лишнего catch», если действия существенны. [Реализация](https://github.com/cqfn/aibolit/blob/1de37051b74fc61ce9313f350487d5807db732db/aibolit/patterns/empty_rethrow/empty_rethrow.py), [fixture](https://github.com/cqfn/aibolit/blob/1de37051b74fc61ce9313f350487d5807db732db/test/patterns/empty_rethrow/CatchWithFunctions.java).
- В jPeek Java-класс `calculus/java/Lcom4` содержит `UnsupportedOperationException`, тесты этой реализации выключены. Это утверждение именно об этой реализации, не обо всём инструменте. [Код](https://github.com/cqfn/jpeek/blob/eb89639b5ab0f989d239a372c759be083c07f8e6/src/main/java/org/jpeek/calculus/java/Lcom4.java), [тесты](https://github.com/cqfn/jpeek/blob/eb89639b5ab0f989d239a372c759be083c07f8e6/src/test/java/org/jpeek/calculus/java/Lcom4Test.java).
- В `LCOM4.xsl` комментарий говорит о компонентах графа, но выражение вычисляет дробную величину из числа пар, полей и методов. При 3 методах, 2 полях и 1 связанной паре формула даёт 1.25, тогда как граф с одной связью имеет 2 компоненты. Это проверка выражения из исходника, не запуск jPeek CLI. Копировать эту формулу как LCOM4 нельзя. [XSL](https://github.com/cqfn/jpeek/blob/eb89639b5ab0f989d239a372c759be083c07f8e6/src/main/resources/org/jpeek/metrics/LCOM4.xsl).
- В Aibolit `CohesionGraph` прекращает обработку после первого класса и фильтрует getters/setters. Для PHP-файлов с несколькими объявлениями такой алгоритм не подходит напрямую. [Код](https://github.com/cqfn/aibolit/blob/1de37051b74fc61ce9313f350487d5807db732db/aibolit/utils/cohesiongraph.py).
- В PATTERNS.md расстояние переменной описано через непустые строки; текущий var_decl_diff считает индексы операторов. Это полезный пример того, почему Soda должна публиковать точную единицу метрики. [Код](https://github.com/cqfn/aibolit/blob/1de37051b74fc61ce9313f350487d5807db732db/aibolit/patterns/var_decl_diff/var_decl_diff.py).

**Философия Soda: практики DHH и Laravel**

DHH прямо описывает concerns как способ разделять поведение без разрастания числа отдельных объектов, допускает concern для одного владельца и оценивает удобство вызова. Он отдельно предостерегает от превращения паттернов в догму. Это конкретная опора для направления Soda. [Concerns](https://signalvnoise.com/posts/3372-put-chubby-models-on-a-diet-with-concerns), [Pattern vision](https://signalvnoise.com/posts/3341-pattern-vision).

В Laravel видны fluent query builder, concern-traits Eloquent и value-object casting. Это свидетельство практики фреймворка; оно не означает личного одобрения наших правил Тейлором Отвеллом. [Query builder](https://laravel.com/docs/13.x/queries), [Model](https://github.com/laravel/framework/blob/13.x/src/Illuminate/Database/Eloquent/Model.php), [value-object casting](https://laravel.com/docs/13.x/eloquent-mutators#value-object-casting).

| Принцип | Что должен поощрять Soda | Как проверять |
|---|---|---|
| Сначала понятный сценарий | По вызову видно намерение; обычная задача не требует знания внутренних Policy/Probe/Factory | Показать примеры вызова до/после; измерить число собственных переходов, не объявляя любое число универсальным порогом |
| Поведение рядом с владельцем | Небольшой private-метод остаётся у владельца; отдельный объект появляется при собственном состоянии, контракте, жизненном цикле или самостоятельной операции | В архитектурном review объяснить пользу каждой выделенной сущности; автоматический детектор — только для прозрачного проксирования |
| Traits как полноценный вариант | Связный concern, использующий состояние хозяина; иногда один потребитель уже достаточен для понятной организации | Положительные fixtures с trait; проверка явных требований к хозяину и конфликтов. Не требовать trait ради количества или ради обхода лимита |
| Fluent там, где читается последовательность | `Report::for($files)->with($rules)->save($path)`; mutating builder и immutable value chain различаются по контракту | Не переносить blanket-запрет method chaining. Проверить тип результата, границы выполнения и явное копирование; не угадывать fluent по префиксу имени |
| VO выражает понятие | `Money`, `DateRange`, `Email` с инвариантами или операциями | Повторяющаяся группа примитивов и её проверки — повод предложить VO. Одноразовый array и простой readonly DTO не должны требовать сервисов и фабрик |
| Меньше посредников | Удаление слоя, который только передаёт аргументы дальше | Расширить NoTrivialDelegatingClasses на несколько forwarding-методов; сохранить реальные адаптеры, контрактные границы, декораторы и named rule API |
| Группировка по функции допустима | Feature-папка может содержать Service и Controller | Не выдавать суффиксы имён за доказательство плохой архитектуры. Реальные циклы зависимостей — отдельная будущая проверка |
| Ранние выходы читаются естественно | Guards не требуют создания пяти новых классов для прохождения лимита return | Сравнительные fixtures guard/else/nesting; пересмотр состава стандартной политики отдельным решением совместимости |

Универсального алгоритма «создай здесь trait/VO» пока нет. Для этих решений первая версия — философия, примеры и предложения при конкретных признаках. Это не основание добавлять эвристический обязательный запрет. Нулевой бюджет нарушений остаётся нулевым для включённых проверок.

LCOM4 особенно важно согласовать с concerns: функциональная группа методов может быть осмысленной без общих полей. Общий logger, наоборот, искусственно связывает разные обязанности. Поэтому ни высокая cohesion, ни количество traits сами по себе не являются оценкой стиля DHH/Laravel. Для прототипа показывать граф отдельно для объявленного класса, каждого trait и разрешённой композиции, с явной маркировкой неполной информации.

**Существующие правила для пересмотра**

| Область | Проблема | Предлагаемое действие |
|---|---|---|
| NoTrivialDelegatingClasses | Пропускает несколько forwarding-методов; сообщение допускает формальное добавление интерфейса как «исправление» | Расширить распознавание, улучшить объяснение; интерфейс не считать автоматически ни доказательством ценности, ни лишним объектом |
| NoBooleanParameters | Путает boolean-данные и режим работы; синтаксически неравномерная readonly-политика | Поддержать эквивалентные формы конструктора; отдельно исследовать использование параметра в выборе поведения |
| NoObjectCloning | Запрещает явную реализацию копирующего API | Различать явное копирование значения и скрытый опасный clone. Ограниченный проверяемый контракт; неизвестные случаи не объявлять доказанно безопасными |
| OnlyListArraysAllowed | Проверка синтаксиса доступа подаётся как архитектурный вывод | Честно описать текущую политику. Рекомендацию VO строить на повторяющейся форме данных/инвариантах; wire-format и данные на границах рассматривать отдельно |
| NoElseBranches + MaxReturnStatements | Одно правило рекомендует то, что другое ограничивает | Подготовить согласованный набор на примерах; старую формулу returns не менять скрытно |
| MaxLayerDominancePercentage | Измеряет имена и организационную конвенцию, не направления зависимостей | Позиционировать как соглашение о структуре или вывести из будущего стандарта после отдельного решения. Не подменять его молча новым алгоритмом |
| Лимиты методов/свойств/длины/зависимостей | Локальная оптимизация может увеличивать число промежуточных классов | Советы должны предлагать оставление рядом, private method, concern или VO по ситуации; порог — повод изучить ответственность, не автоматическая инструкция split |
| PHPDoc для всего | Наличие многострочного текста не доказывает полезность документации | Сохранить текущие требования, но в примерах показывать смысл, инварианты и контракт. Не считать сгенерированное описание очевидного признаком качества |
| NoTodoFixmeComments | Политика запрета TODO не универсальный признак завершённости | PDD показывает альтернативу: связанный с задачей долг. Возможный отдельный инструмент позже, без изменения нынешнего запрета и без добавления подавлений |

**Другие проекты**

- [PDD](https://github.com/cqfn/pdd): полезен для прослеживаемости технического долга и качества описания TODO; это иной рабочий процесс, не новый AST-анализатор. Не внедрять автоматическое создание задач в Soda в этой итерации.
- [Qulice](https://www.qulice.com/quality.html): полезны единый запуск проверок и понятные условия приёмки. Отдельные Java-проверки следует брать у непосредственных реализаций, а не переносить Maven-конфигурацию.
- [Veniq](https://github.com/cqfn/veniq): исследование Extract Method, архивировано. Возможный источник размеченных вариантов рефакторинга, не runtime-зависимость.
- [UAST](https://github.com/cqfn/uast), [Astranaut](https://github.com/cqfn/astranaut): инфраструктура деревьев и преобразований. Сейчас не решает задачу качества правил Soda; отдельная универсальная модель увеличила бы объём системы. nikic и нынешний AST сохраняются.
- [Refrax](https://github.com/cqfn/refrax), [Aibolit MCP](https://github.com/cqfn/aibolit-mcp-server): выполнение/доставка рекомендаций; по описанию не приоритетный источник новых правил. Глубокий аудит этих реализаций не проводился.

**Порядок реализации**

1. Зафиксировать философию и небольшой набор эталонных PHP-примеров: богатый объект с concern, fluent builder, immutable chain, readonly DTO, VO с инвариантом, понятный procedural helper, полезный adapter и бесполезная forwarding-цепочка. Рядом — контрпримеры из текущего аудита. Сначала оценить, какие именно включённые правила наказывают желаемую форму.
2. Отдельным PR улучшить NoTrivialDelegatingClasses и равномерность политики boolean-состояния. Все новые условия подтвердить positive/negative tests; сохранить семантику параметров и фактическое состояние объектов.
3. Отдельным PR обновить сообщения и рекомендации: перестать безусловно советовать новый класс. Подготовить решения по clone, guards/returns, именам папок и массивам; каждое изменение поведения стандартного набора обозначить явно. В 1.x новые эвристики остаются opt-in; не переопределять незаметно старые идентификаторы и пороги.
4. Перенести два небольших детектора обработки исключений как именованные Check-классы с PHP-адаптациями и атрибуцией. Сначала opt-in, без изменения стандартного состава и без auto-fix.
5. Исследовательским PR добавить Cognitive Complexity и граф cohesion. LCOM4 рассчитывать собственным небольшим алгоритмом компонент; для TCC определить точную версию формулы. Новые факты регистрировать с единицами и происхождением. Никакого Python/Java/XML runtime в Soda, phplrt остаётся внутренним инструментом сравнений.
6. Проверить полезность на фиксированном PHP-корпусе: Soda, компоненты Laravel и Symfony, Monolog, Guzzle, плюс небольшой прикладной проект при его доступности. Зафиксировать версии, роли файлов и выборку до изменения порогов. Рассмотреть минимум 100 диагностик кандидатов, если их столько есть, и случайную выборку непроблемных мест; при малом числе сообщить фактический объём. Отдельно учитывать лишние срабатывания и пропуски. Часть проектов оставить для контрольной проверки без подстройки.
7. После результатов решить, что достойно стандартного набора. Паттерн, который просто заставляет переименовать папку или добавить посредника, не проходит приёмку как архитектурное улучшение. Если точность/польза не подтверждена, оставить измерение или отказаться от правила.

**Приёмка**

- Для каждой новой или изменённой проверки есть определение, область применения, исходный источник, формула либо AST-критерий, контрпримеры и объяснение рекомендации.
- Донорские тесты не копируются с ожиданиями вслепую: Java → PHP сопровождается записью, что сохранено и что изменено; сторонние баги не становятся нашим контрактом.
- Метаморфные тесты проверяют, что форматирование, перенос строк и переименование локальных переменных не улучшают семантическую метрику. Для правил имён такие преобразования, естественно, не обязаны быть инвариантными.
- Cohesion: независимые классы, связующие вызовы, общий технический logger, DTO, constructor, static/private, trait aliases/conflicts, inheritance, anonymous classes и dynamic calls. Неизвестные связи отмечаются, а не считаются отсутствующими; не вводить класс-обёртку ради каждого ребра графа.
- Cognitive Complexity: линейный код, guards, вложенные условия и циклы, boolean-группы, try/catch/finally, match, recursion, closures. Каждый балл объясним; никакого нового составного рейтинга.
- Простая PHP-проверка добавляется через класс, регистрацию и тест; текущий Runner менять не требуется. Межфайловые алгоритмы сохраняют компактные факты без AST и исходного текста, каждый файл разбирается один раз.
- Примеры trait/fluent/VO проверяются по выбранному контракту каждой проверки; это не требование всем существующим строгим правилам молча пропускать любые такие конструкции.
- Поведенческие тесты, self-quality без бюджетов нарушений, PHPStan, Pint, Rector и текущие ограничения времени/памяти проходят. Производительность измеряется отдельно от параллельных тяжёлых проверок.
- В review показывается сценарий чтения и изменения до/после. Меньше файлов — полезный результат только при сохранении понятных обязанностей; число строк и оценки «10/10 от эксперта» не считаются доказательством.

**Использование чужого кода и тестов**

Корневые лицензии [Aibolit](https://github.com/cqfn/aibolit/blob/1de37051b74fc61ce9313f350487d5807db732db/LICENSE.txt) и [jPeek](https://github.com/cqfn/jpeek/blob/eb89639b5ab0f989d239a372c759be083c07f8e6/LICENSE.txt) — MIT: код можно копировать и адаптировать с сохранением copyright и текста разрешения в копиях/существенных частях. При переносе записать repository, commit, source file, лицензию и изменения в одном документе атрибуции; оригинальные notices сохранить.

Не все fixtures автоматически ограничены корневой MIT. Например, `test/patterns/empty_rethrow/DataBaseNavigator.java` содержит также заголовок Apache-2.0 DBeaver. Поэтому в первую очередь брать небольшие собственные MIT-примеры проектов; сторонние полные файлы проверять по их собственным notices. Этот аудит ничего из донорского кода в Soda не добавляет.
